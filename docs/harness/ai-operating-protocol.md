# AI·사람 공통 행동 규약

> 범위: **공통** (`PTK_V2_FE` · `PTK_V2_BE` 동일). 출처 태그 정의는 `README.md` 참고.
> 목적: 작업자가 누구든, 어떤 AI 도구를 쓰든 **같은 입력에 최대한 같은 결과**가 나오게 한다.

## 1. 시작과 우선순위

- **P-1 [D]** 작업을 시작하기 전에 `README.md` §1 의 읽는 순서대로 문서를 **끝까지** 읽는다. 읽지 않고 시작하지 않는다.
- **P-2 [D]** 우선순위는 `사용자 최신 지시 > 하네스 > 코드 관행 > AI 일반 습관` 이다. 서로 충돌하면 임의로 고르지 말고 사용자에게 묻는다.
- **P-3 [U 2026-11-25]** **요청받은 범위만** 수행한다. 사용자가 계획을 요청했으면 계획만 쓰고 구현하지 않는다. "지금 계획 세우는 거야? 아니면 멈춰"라는 질문을 받으면 즉시 하던 일을 멈추고 현재 상태를 답한다.
- **P-3b [U 2026-11-27]** 사용자가 "지시 확인 후 계획을 세워서 확인 받고 진행"을 요구하면 **계획 제시 → 사용자 승인 → 실행** 순서를 지킨다. 승인 전에는 파일·원격 저장소·외부 서비스를 바꾸지 않는다.
- **P-4 [D]** 모호하면 추측하지 말고 질문한다. 선택지를 2~4개로 제시하고 **추천안을 맨 앞**에 둔다. 사소한 예/아니오 질문은 평문으로 묻는다.

## 2. 사실에 기반한 작업과 보고

- **P-5 [D]** 보고는 **실제로 실행한 명령과 그 출력**에만 근거한다. 실행하지 않은 검증을 했다고 쓰지 않는다. 실패·건너뜀·제외한 항목은 이름까지 적는다. 모든 검사가 통과했다는 말은 실패 0건인 실행 결과가 있을 때만 쓴다.
- **P-6 [D]** 파일을 바꾸기 전에 **먼저 읽는다.** 기억이나 일반 지식으로 코드·설정·수치를 채우지 않는다.
- **P-7 [D]** 요청과 무관한 리팩터링·포맷 변경·의존성 추가를 섞지 않는다. 필요하면 별도 이슈로 만든다. 의존성을 추가할 때는 이슈 본문에 이유를 적는다.
- **P-8 [D]** 문서·코드·규칙이 서로 어긋나면 같은 PR 에서 함께 고친다 (API 를 바꾸면 API 문서, 구조를 바꾸면 `architecture.md`).

## 3. 사용자 품질 기준

- **P-9 [U 2026-11-27]** 수정을 진행하면서 **사용자 경험(UX)이 지저분해지면 안 된다.** 처음 보는 사람도 쉽게 쓸 수 있어야 한다.
- **P-9b [U 2026-11-27]** **백엔드 로직이 지저분해지지 않게** 하고, 지금 잡은 개선 방향보다 **더 좋은 방향이 있는지 항상 먼저 생각하고** 개발한다. **[D]** 구현 전에 대안을 한 번 검토하고, 채택 이유를 PR 본문 `## 그 외` 에 한 줄로 남긴다.

## 4. 안전

- **P-10 [D]** 아래 작업은 **사용자가 그 작업을 명시적으로 승인했을 때만** 한다: `main` force push · 공유 브랜치 `reset --hard` · 레포/브랜치 삭제(머지 끝난 작업 브랜치 정리는 제외) · 사용자 데이터·산출물 삭제 · 레포 설정/보호 규칙 변경.
- **P-11 [U 2026-11-28]** 두 레포는 배포를 위해 **PUBLIC** 으로 유지하지만 회사 내부 서비스이므로, API 키·토큰·`.env` 뿐만 아니라 **실제 고객사(클라이언트)명·제안서/팩트북 원본·실측 수치·내부 참고 URL·내부 계정/인프라 정보 등 기밀이 될 수 있는 어떤 내용도 코드·문서·테스트·이슈·PR·커밋 메시지에 절대 올리지 않는다.** 키는 BE `.env` 에만 두고 FE 와 레포 어디에도 넣지 않는다. 문서·테스트·예시는 가명(`샘플 브랜드 A` 등)과 합성 데이터만 사용한다. 출력·로그에 키가 보이면 마스킹한다.
- **P-12 [D]** 외부 시스템(GitHub 등)은 **사용자가 이미 로그인해 둔 공식 CLI**(`gh`) 로만 접근한다. 토큰을 코드·문서에 적지 않고, 권한 오류가 나면 **우회하지 말고 보고하고 멈춘다.**
- **P-13 [D]** 사용자의 다른 프로젝트·프로세스를 건드리지 않는다. 포트가 이미 점유돼 있으면 점유 프로세스를 끄지 말고 다른 포트를 쓴 뒤 보고한다.

## 5. 결정성(같은 결과를 내기 위한 습관)

- **P-14 [D]** `verification.md` · `environment.md` 의 **명령을 문서 그대로** 실행한다 (임의로 옵션·순서를 바꾸지 않는다).
- **P-15 [D]** 런타임 버전(Node · Python)과 lockfile(`package-lock.json`)을 지킨다. 설치는 FE `npm ci`, BE `pip install -r requirements.txt` 로 한다.
- **P-16 [D]** 응답은 **한국어**로 쓴다. 코드 식별자·명령·경로는 원문 그대로 쓴다.
- **P-17 [D]** 작업 완료 보고는 항상 이 4가지를 담는다: ① 무엇을 했나 ② 이슈·PR 링크 ③ 검증 명령과 실제 결과 ④ 남은 일·위험·사용자 결정이 필요한 사항.

## 6. 규칙 추가

- **P-18 [U 2026-11-27]** 대화 중 사용자가 새 규칙·선호를 말하면 **임의로 하네스에 추가하지 않는다.** 반드시 사용자에게 **먼저 물어보고**, 승인된 것만 `rule-changes.md` 절차로 추가한다.
